# Phase F3.5 — Design Source Audit

Authoritative design lives in `docs/design/source/` (28 PDFs). This audit maps every
artifact → the screen it represents → its route → the backend capability it exposes →
the existing application service/read-model it consumes → the current implementation
gap. **No backend was created for F3.5** — where a designed feature has no read model,
it is marked **Future Phase** rather than faked.

## Design system (00, 08 DNA, 09 Handoff — reference, not routes)
- **00-Design-System / 08-Auxion-DNA**: the visual contract. Already implemented as the
  `@brightloop/ui` canon tokens + primitives: `--bg/--surface/--surface-2/--ink(-2/-3)/--line/--line-strong`,
  amber `--signal`, `--positive/--caution/--critical/--info`; Space Grotesk (display) / IBM
  Plex Sans (body) / IBM Plex Mono (data); motion curves Precise 240ms / Orchestrate 440ms
  / Enter 640ms; radii 6-8/11/14/16-18/999; primitives `SectionRule` (§NN), `IndexGauge`,
  `SystemMap`, `OperationalTable` (ledger), `MetricCard`, neutral-pill `Badge`,
  `ActivityTimeline`, `DetailGrid`. **The ONE HARD RULE** (status = neutral pill: surface-2
  fill + 1px line + colored dot + colored mono text, never colored fill behind colored text)
  is enforced by `Badge` and applied with `dot` across the workspace in F3.5.
- **09-Rebrand-Migration-Handoff**: app shell = 248px rail (identity console + nav +
  operator) + 60px topbar + **blueprint dot-grid** scrolling main; client-facing views drop
  the rail for a centered read. → shell dot-grid added in F3.5.
- **27-Business-Scan-Engine**: backend/AI engine spec — no route.

- Blueprint dot-grid backdrop on the scrolling main (§06).
- Neutral-pill status chips with `dot` across all workspace status badges (the ONE HARD RULE).
- `SectionRule` §NN headers + `IndexGauge` + `MetricCard` on the Command Center.
- Loading skeletons, error boundaries, not-found, and consistent empty states on every route.
