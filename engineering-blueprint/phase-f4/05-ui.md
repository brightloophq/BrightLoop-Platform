# F4.1 · UI

Dark-first product UI under `/workspace/integrations`, matching the F1/F3.5
conventions and reusing the design system + `apps/web/src/app/workspace/pages.module.css`.
Nav item `Integrations` (icon `plug`, added to the UI `Icon` map) sits between
Runtimes and Executions; a command-palette entry (`go-integrations`) mirrors it.

## Routes

| Route | Purpose | Template basis |
|---|---|---|
| `/workspace/integrations` | Installed Connectors list — health tone + status pill per row | `workspace/runtimes/page.tsx` |
| `/workspace/integrations/marketplace` | Connector Marketplace grid; annotates installed vs available vs example | `workspace/ai-team` `teamGrid` |
| `/workspace/integrations/marketplace/[connectorId]` | Connector Details: capabilities, triggers, config schema, install form | detail + form |
| `/workspace/integrations/[installationId]` | Installation Details: status/health, config, capabilities, controls, event/health/audit streams | `workspace/runtimes/[id]` |

## Client components

- `InstallForm.tsx` — renders the descriptor's `configFields` (secret fields as
  `password` inputs, enum fields as selects), calls `installConnectorAction`, and on
  success routes to the new installation. All validation + the secret boundary live in
  the use-case; the form only collects.
- `ConnectorControls.tsx` — validate / check-health / enable / disable / revoke,
  each a `useTransition` call to a server action; available actions are gated by the
  installation's lifecycle status; only a safe `ActionResult.error` is surfaced.

## Server actions (`actions.ts`)

`"use server"`, the C1 `run()`/`fail()` helper: `buildAppContext()` → use-case →
`revalidatePath`. `installConnectorAction` resolves the workspace and returns the new
installation id for client-side navigation. Never leaks a stack, SQLSTATE, provider
body, or secret — only a canonical `ApplicationError` message.

## States & honesty

- Every route ships `force-dynamic`; the workspace shell already provides
  `loading.tsx` / `error.tsx` / `not-found.tsx` (cascade to nested routes).
- Every status renders as a neutral-pill `Badge … dot` (the F3.5 rule); health tones
  come from a small local helper.
- Example connectors (no live adapter) are honestly labelled and show a notice
  instead of a fake install form — no fabricated capability.
